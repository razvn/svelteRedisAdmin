A modern Redis administration tool

svelteRedisAdmin is a fresh take on phpRedisAdmin: a fast, clean dashboard to browse and edit keys of every type, run commands, monitor servers and manage who can do what — with light and dark themes and English, French and Spanish interfaces.

Features

Everything you expect from a Redis admin tool

Feature parity with phpRedisAdmin where it makes sense, rebuilt with a modern interface, a typed codebase and a maintainable test suite.

  • Key browser

    A SCAN-based browser per database with cursor pagination, glob and type filters, type badges, TTL pills, a list or tree view grouped by key separator, and bulk delete with a guarded flush.

  • Editors for every type

    View and edit strings (with JSON pretty-print), hashes, lists, sets, sorted sets and streams. Rename keys, edit or persist TTLs, add entries — binary values round-trip losslessly as base64.

  • Command console

    Run commands against any database, one per line, with redis-cli quoting rules, # comments, per-command timing and a recursive, color-coded reply renderer. SHUTDOWN and MONITOR are refused.

  • Server monitoring

    Overview stat cards and keyspace tables, a browsable INFO report, CONFIG get and set with search, the connected client list with kill, and the slow log with reset.

  • Export and import

    Download a whole database as JSON — every key with its type, TTL and value — and re-import it later, including the binary-safe records. Filters apply to both directions.

  • Users, roles and pluggable auth

    Per-user admin / rw / ro roles and per-user server visibility, enforced server-side on every destructive action. Authentication is pluggable: config list, HTTP Basic, or a trusted ingress identity header for SSO deployments.

  • Internationalized

    English, French and Spanish today, with gettext-style catalogs keyed on the English source and a documented one-folder way to add more languages.

  • Built for Kubernetes

    One deployment for many Redis servers: identify users at the ingress, map them to the servers they may see, and get 404s — not leaks — for the rest. Dynamic discovery from ConfigMaps or labels is on the roadmap.

Users & authentication

Who can do what, enforced where it matters

The UI hides what a role may not do — but the boundary is the server: every destructive action re-checks the role, and servers a user cannot see answer 404.

  • Three roles. admin manages everything, rw edits data, ro browses read-only. Roles live in the login config entries.
  • Per-user server visibility. A servers allowlist filters the sidebar and the switcher; anything else answers 404 so server existence is not leaked.
  • Pluggable authentication. Pick a plugin in auth.plugin: the config login form, HTTP Basic, or header to trust X-Forwarded-User from oauth2-proxy, Istio or Cloudflare Access — the Kubernetes pattern.
  • Signed sessions. An HMAC-signed, http-only cookie caches the plugin's decision; Redis connections use the server's own credentials and never expose secrets to the browser.

Quick start

Up and running in two minutes

# dev Redis on :33380 (seeded) and :33381
pnpm db:up

# configure servers and logins
cp config.sample.json config.json

# start the app
pnpm dev

Then open http://localhost:5173 and sign in with the credentials from config.json. For production, the same image runs as a plain Node server: pnpm build then node build/index.js.
