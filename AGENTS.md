# svelteRedisAdmin — conventions for implementer agents

A SvelteKit + Svelte 5 re-implementation of **phpRedisAdmin**
(https://github.com/erikdubbelboer/phpRedisAdmin). Read `docs/ROADMAP.md` first (architecture,
routing tree, phases) and `docs/DESIGN.md` for the look. Reference behaviour: the phpRedisAdmin
README/repo (read-only, external).

## Stack

SvelteKit (adapter-node), Svelte 5 **runes**, TypeScript strict, Tailwind CSS v4,
shadcn-svelte (bits-ui 2) + mode-watcher, zod, `redis` (node-redis v5), Vitest, Playwright, pnpm,
Node >= 22.

## Folder layout

```
src/
  app.css                  Tailwind + shadcn-svelte theme tokens (CSS variables, class-based .dark on <html>)
  lib/
    components/ui/         shadcn-svelte components (generated by the CLI, then owned by us)
    components/            our own composed components (theme-toggle, app shell, ...)
    hooks/                 shared hooks (.svelte.ts), e.g. is-mobile
    utils.ts               cn() and shadcn type helpers
    server/                SERVER-ONLY code (never import from client code)
      config/              config.json loader + zod schema (phpRedisAdmin-compatible keys)
      auth/                signed-cookie session (HMAC), login/logout actions
      redis/               connection manager, key-type services, serializers, info/config readers
  routes/                  see ROADMAP "Routing"
e2e/                       Playwright specs (*.e2e.ts)
docker/initdb/             seed script for the dev Redis instances
config.sample.json         committed sample; config.json is git-ignored (override path: SRA_CONFIG)
```

## Rules

- **Svelte 5 runes only**: `$state`, `$derived`, `$effect`, `$props`, snippets, `{@render}`. No `export let`,
  no `$:`, no `on:click` (use `onclick`), no `<slot>`, no Svelte stores unless a genuinely shared
  cross-component subscription is required (prefer `.svelte.ts` modules with `$state`).
- Use the Svelte MCP `svelte-autofixer` on every new/changed `.svelte` file.
- **Server-only code lives in `src/lib/server/`** (SvelteKit blocks client imports). Never expose
  secrets, `cookieSecret` or raw connection errors to the browser.
- **Validate all input with zod** (form actions, `+server.ts`, query params). Parse, don't trust.
- Key names are raw bytes: never assume UTF-8. Values that are not valid UTF-8 are returned to the
  UI base64-tagged (`{kind: 'binary'}`) — never decoded lossily.
- **Destructive actions** (delete, rename, flush, CONFIG SET, CLIENT KILL, SLOWLOG RESET) always go
  through form actions or POST endpoints with zod-validated input; never mutate from a GET.
- Keep config key names compatible with phpRedisAdmin (see `config.sample.json`).
- Style: tabs, single quotes, no trailing commas (Prettier enforces it: `pnpm format`).
- Imports: only the `#lib/*` alias (package.json `imports`) with explicit extensions, e.g.
  `import { cn } from '#lib/utils.ts'`. Never `$lib` (not generated in SvelteKit 3).
- **Before writing any Svelte/SvelteKit code, load the project skill `.claude/skills/sveltekit-3/SKILL.md`**
  plus the svelte plugin skills (`svelte:svelte-core-bestpractices`, `svelte:svelte-code-writer`); the
  project skill wins wherever they assume SvelteKit 2.
- **UI = shadcn-svelte.** Use the components in `#lib/components/ui` (bits-ui 2 based); add missing ones with
  `pnpm dlx shadcn-svelte@latest add <name>` (then fix generated imports to `#lib/...ts` if needed). Do not
  hand-roll what shadcn-svelte provides. Icons come from `@lucide/svelte` (`@lucide/svelte/icons/<name>`).
  Style only with theme tokens (`bg-background`, `text-foreground`, `text-muted-foreground`, `border`,
  `bg-primary`, ...), never raw colours. Light/dark/system via `mode-watcher` (`ModeWatcher` in the root layout).

## i18n

gettext-style, hand-rolled in `src/lib/i18n/` (mirrors svelteMyAdmin): **msgids are the English source
strings**; translations live in flat JSON catalogs at `src/lib/i18n/locales/<lang>/<area>.json`
(`fr`, `es` today). English never needs a catalog. Adding a language = one line in
`languages.ts` + one catalog folder.

- **Client components**: `const i18n = useI18n(); const t = $derived(i18n.t);` then `{t("Delete")}`.
  `$derived` is required (a plain const breaks reactivity on language switch).
- **Server loads/actions**: `const t = locals.i18n.t;` (`locals.i18n` is set in `hooks.server.ts` from the
  `sra_lang` cookie, then `Accept-Language`, then `en`). Return translated strings in page data.
- Params interpolate as `{name}`; plurals via `t("{n} key", "{n} keys", n)` and catalog arrays in CLDR
  category order. HTML-bearing strings use `{@html i18n.t('... <code>...</code> ...')}` — never with
  user data.
- Language switch: `POST /api/lang` sets the cookie, then `refreshAll()` (`setLanguage()` in
  `#lib/i18n/switch.ts`); the top-bar language dropdown does this.
- `data-testid` values stay English literals; user-visible `aria-label`s are translated.

## UI design

The look (grey canvas, white rounded cards, indigo primary, soft status pills) is specified in
`docs/DESIGN.md`: tokens, `PageHeader`/`StatCard`, badge variants, table and card conventions, do/don't.
Start every page with `app-shell/page-header.svelte`, use only theme tokens and the shared components, and
verify light + dark at 1440 px and 800 px.

## Tests are mandatory with every feature

| Kind        | File name                    | What                                                                                                  |
| ----------- | ---------------------------- | ----------------------------------------------------------------------------------------------------- |
| Unit        | `*.test.ts` next to the code | pure logic (config schema, serializers, key parsing)                                                  |
| Component   | `*.svelte.test.ts`           | Svelte components in a real browser (`vitest-browser-svelte`)                                         |
| Integration | `*.integration.test.ts`      | commands against Docker Redis (:33380, second instance :33381); must skip gracefully when unreachable |
| E2E         | `e2e/*.e2e.ts`               | critical user flows (Playwright)                                                                      |

Never weaken or delete a test to make it pass: fix the code.

Integration tests use db **0..3** of the :33380 instance (port `REDIS_TEST_PORT`, default `33380`)
and must flush only databases 0-3 in their fixtures. Dev servers: `redis1` (:33380) and `redis2`
(:33381) via `pnpm db:up`.

Test conventions: temporary keys are prefixed `sra_test:` so they can be cleaned up without
touching real data. Never flushall in tests.
